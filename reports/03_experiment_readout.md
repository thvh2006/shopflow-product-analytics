# Synthetic Experiment Readout

## Evidence decision

**Do not infer a product launch from this simulation.** The healthy run verifies that
the analytical pipeline can recover an injected effect while enforcing assignment,
balance, uncertainty, and guardrail checks. The source contains only 9,742 unique
eligible users—below the 16,782-user planning floor—and every post-assignment outcome
is generated by code with a positive effect built in.

## Trust checks first

- Assignment: 4,862 control and 4,880 treatment users.
- Source-user uniqueness: 9,742 unique users and **zero duplicates**.
- SRM chi-square `p = 0.855`, above the preregistered 0.001 failure threshold.
- Maximum absolute covariate SMD: 0.016, below the 0.10 threshold.
- Runtime: all 14 generated experiment days represented.

The effect is interpreted only after these checks pass.

## Primary outcome

| Metric | Control | Treatment | Absolute effect | Relative lift | 95% CI | p-value |
|---|---:|---:|---:|---:|---:|---:|
| Same-product conversion | 43.71% | 46.58% | +2.87 pp | +6.57% | +0.90 to +4.84 pp | 0.004 |

The confidence interval excludes zero, but the generator injects a 0.12 base
log-odds treatment effect. Detection therefore checks implementation; it is not
independent evidence for the interface.

## Secondary and guardrail outcomes

- Purchase-item value per eligible user increases by 4.98 source-value units (95% CI −1.60 to 11.57); the interval includes zero.
- CUPED-adjusted value increases by 5.07 (95% CI −1.50 to 11.63), with only 0.57% variance reduction.
- Checkout latency increases by 18.27 ms (95% CI 11.49 to 25.05), below the illustrative +50 ms guardrail.
- Error-event rate is 0.74% in control and 0.64% in treatment.

Daily estimates are noisy, as expected at one-fourteenth of the pooled sample. The pooled result is not driven only by the first two novelty days.

## Power and A/A validation

At the 42.94% planning baseline, a 5% relative lift requires 8,391 users per arm.
The unique source population supplies only 4,862 and 4,880 users per arm—**7,040
total users below plan**. A 2% relative lift would require 52,273 per arm. The code
refuses to sample with replacement to make the experiment appear adequately powered.

Across 5,000 simulated A/A experiments with 5,000 users per arm, the false-positive rate is 5.18% at nominal alpha 5%, the mean estimated effect is approximately zero, and p-value deciles are close to uniform. This validates the calculation path under simulation; a production assignment service would still need a live A/A.

## Heterogeneity and temporal stability

| Exploratory segment | Control | Treatment | Effect | 95% CI |
|---|---:|---:|---:|---:|
| First-observed users | 42.62% | 45.66% | +3.04 pp | +0.90 to +5.19 |
| Returning users | 49.73% | 51.50% | +1.77 pp | −3.27 to +6.80 |
| Days 1–2 | 43.93% | 47.20% | +3.26 pp | −1.97 to +8.47 |
| Days 3–14 | 43.67% | 46.47% | +2.80 pp | +0.67 to +4.93 |

The treatment-by-returning interaction has `p = 0.639`; the treatment-by-early-window
interaction has `p = 0.874`. There is no evidence that effects differ across these slices.

## Red-team telemetry scenario

A second generated dataset deliberately drops treatment telemetry more often. It
leaves 4,843 control versus 4,319 treatment records and produces SRM `p < 5e-8`.

Its primary effect is also statistically significant, but it is **not interpretable**. This demonstrates the operational rule: a persuasive p-value cannot rescue broken assignment or telemetry. Sensitivity analysis shows that 5% differential treatment telemetry loss is enough to cross the preregistered `p < 0.001` SRM threshold at this sample size, while 1–2% loss may not; SRM is a detector, not a complete data-quality guarantee.

## Required next steps

1. Expand or extend eligibility until the preregistered real-user sample can be reached.
2. Implement assignment, render, checkout, cancellation, and refund contracts.
3. Run a live A/A before treatment.
4. Run the user-randomized test with a persistent control and mature outcomes.
5. Make a launch decision only from observed experimental outcomes.

## Scope warning

The observational backbone uses real anonymised event records, while treatment assignment and all experiment outcomes are generated by published code with a fixed seed. The readout demonstrates analytical practice; it is not evidence that a real company shipped or benefited from this feature.
